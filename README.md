# akko

ファイルを暗号化・復号化するCLIツール。

## インストール

```sh
go build -o akko .
```

## 前提条件

- Go 1.27以上

## 使い方

入力ファイルが通常ファイルなら暗号化、`akko`独自フォーマットの暗号ファイルなら復号化する。
`enc` / `dec` のようなサブコマンドはない。

### キーファイルを指定する

```sh
akko -key key.txt secret.txt   # 暗号化 -> secret.txt.akko
akko -key key.txt secret.txt.akko  # 復号化 -> secret.txt
```

`-key` は常にキーファイルへのパスとして扱う。パスワード文字列を直接渡すことはできない（ファイル名の指定ミスとパスワード入力の意図を区別できなくなるため）。指定したファイルが存在しない場合はエラーになる。

### パスワードを対話入力する

```sh
akko secret.txt
Password:
```

`-key` を省略すると、端末上でエコーされない入力でパスワードを尋ねる。

### 出力先を指定する

```sh
akko -output out.akko secret.txt
akko -o out.akko secret.txt
```

省略時は、暗号化は `<input>.akko`、復号化は元の拡張子を復元したパスがデフォルトの出力先になる。

### 有効期限を設定する（`-expiry`）

```sh
akko -key key.txt -expiry "2026/08/22 20:00" secret.txt
```

`-expiry` を指定すると、暗号化ファイルに有効期限を埋め込む。書式は `YYYY/MM/DD HH:MM`（ローカルタイム）。分単位指定のため、その分の末尾（`HH:MM:59`）までは復号でき、次の秒（`HH:MM+1:00`）以降は復号を拒否する。`-expiry` を省略した場合は無期限。

`-header` で有効期限を表示する場合は、`YYYY/MM/DD HH:MM TZ (UTC±HH:MM)` 形式でタイムゾーンを明示表示する。

### ファイルパーミッションの維持

暗号化時に元ファイルのパーミッション（読み書き実行権限）をヘッダーに保存し、復号時にそのパーミッションを復元する。`-archive` でまとめた場合も、アーカイブ内の各ファイルごとに個別のパーミッションを保存・復元する。

## Windows/Mac/Linux間の互換性

`.akko` ファイル形式自体はOS/CPUアーキテクチャに依存しない固定長バイナリ形式で、暗号アルゴリズム（AES-256-GCM）とKDF（Argon2id）もOS非依存のGo実装のため、暗号化と復号を異なるOS間で行っても問題ない（例: macOSで暗号化したファイルをWindowsで復号できる）。キーファイルの改行コード（`\r\n` / `\n`）もどちらも許容する。

ただし、パーミッション維持機能はUnix系のrwxビットをそのまま保存・復元する設計のため、Windowsでは意味が異なる。

- Windowsには本来のUnixパーミッション概念がなく、`os.Chmod`は読み取り専用属性のON/OFFしか制御できない。
- macOS/Linuxで暗号化したファイルをWindowsで復号しても、パーミッションは正しく再現されない（エラーにはならないが情報が活きない）。
- Windowsで暗号化したファイルをmacOS/Linuxで復号すると、Windows側の疑似パーミッション値がそのまま復元され、元のUnixパーミッションとは異なる場合がある。

### フォルダを指定する（`-r`）

```sh
akko -key key.txt -r some_dir
```

入力にディレクトリを指定する場合は`-r`が必須。`-r`を付けると、ディレクトリ内のファイルを再帰的に探索し（サブフォルダも対象）、見つかった通常ファイルすべてを処理対象に加える。シンボリックリンク（ファイル・ディレクトリどちらも）は実体を持たないため探索・処理の対象外。`-r`を付けずにディレクトリを指定するとエラーになる。

### 既存の出力ファイルを上書きする

```sh
akko -force secret.txt
```

`-force` を付けない限り、既存の出力ファイルは上書きしない。

### 複数ファイルをワイルドカードで指定する

```sh
akko -key key.txt sample_*.txt
akko -key key.txt -force sample_*.akko
```

ワイルドカードパターンは`akko`自身が展開するため、シェルが展開しない環境でも動作する。マッチした各ファイルは暗号化・復号化どちらも通常ファイルかどうかで個別に判定される。複数ファイルにマッチした場合、`-output` / `-o` での出力先指定はできない（出力先が一意に決まらないため）。一部のファイルの処理に失敗しても他のファイルの処理は継続し、1件でも失敗があれば終了コードは非ゼロになる。

引数に`*` `?` `[` などのワイルドカード文字が含まれる場合、事故防止のため対象ファイルの一覧を表示し、続行するかどうかの確認（`y/N`）を求める。`y` / `yes` 以外の入力は処理を中断する。シェルが`*`などを事前に展開してしまい引数自体にワイルドカード文字が残らない場合でも、結果的に複数ファイルが対象になっていれば同様に確認を求める。

### 複数ファイルを1つの暗号化ファイルにまとめる（`-archive`）

```sh
akko -key key.txt -archive -output bundle.akko a.txt b.txt c.txt
```

`-archive` を付けると、暗号化対象の入力ファイルを1つのtarアーカイブにまとめてから暗号化する（出力は`bundle.akko`のような単一ファイル）。`-output` を省略した場合は、カレントディレクトリの `archive.akko` に出力する。各ファイルは指定時の相対パス（先頭の`/`や`..`は除去される）を保ったままアーカイブに格納されるため、`-r`でディレクトリを指定した場合もフォルダ構造が復号時に復元される。アーカイブ内のエントリ名（パス）が重複する場合は暗号化時にエラーになる。

アーカイブファイルであるかどうかはヘッダーに保存され、復号時に自動判定される。そのため復号時は `-archive` を付ける必要はなく、通常どおり対象ファイルを指定するだけでよい。

```sh
akko -key key.txt -output extracted/ bundle.akko
```

`-output` に出力先ディレクトリを指定すると、そこにアーカイブ内の各ファイルが元の相対パス（フォルダ構造込み）で展開される。省略した場合はカレントディレクトリ（`.`）に展開する（実装上の挙動）。展開先に既存ファイルがあり `-force` を付けていない場合はエラーになる。

## 暗号ファイルフォーマット

`akko`ファイルは自己記述型の独自バイナリフォーマット。

```text
Magic ("AKKO", 4 bytes)
Version (1 byte)
Algorithm ID (1 byte)
KDF ID (1 byte)
KDF Parameters (memory, iterations, parallelism)
Salt (16 bytes)
Nonce base (8 bytes)
Original file extension length + extension
Expiry unix time (8 bytes, 0 means no expiry)
--- 以下、チャンクごとに繰り返し ---
Chunk length (4 bytes)
Chunk ciphertext + authentication tag (AES-256-GCM)
```

- ヘッダー全体（Magic〜拡張子まで）はAES-GCMのAAD（Additional Authenticated Data）として認証され、改ざんを検出できる。
- ファイルはチャンク単位でストリーミング暗号化・復号化されるため、巨大なファイルでもメモリに全体を読み込まない。
- 各チャンクのnonceは、暗号化ごとにランダム生成されるnonce baseとチャンク番号から一意に導出され、再利用しない。

## セキュリティ

- KDFにArgon2id、暗号にAES-256-GCMを使用する。独自の暗号アルゴリズムは実装しない。
- パスワードを直接AES鍵にせず、Argon2idで32byte鍵を導出する。saltは暗号化ごとにランダム生成し、ヘッダーに保存する。
- 復号は一時ファイルに出力し、認証成功後にのみatomic renameで最終ファイルへ反映する。認証失敗時や途中エラー時は最終出力ファイルを残さない。
- 鍵の誤りと暗号文の改ざん・破損は、どちらもAES-GCMの認証失敗として同一に扱い、攻撃者に不要な情報を与えない。
- `-key`はキーファイル専用で、パスワード文字列の直接指定はできない。パスワードを使う場合は`-key`を省略し、対話入力（非エコー）を使うこと。これにより、シェル履歴・プロセス一覧への漏洩と、ファイル名指定ミス時の意図の取り違えを防ぐ。
- 既に暗号化された`akko`ファイルはMagicにより自動的に復号対象と判定されるため、二重暗号化はされない。

## 互換性/バージョニング

- ヘッダーに`Version`フィールドを持ち、未対応バージョンのファイルは安全に拒否する。
- 初期バージョン（v1）でサポートするアルゴリズムはAES-256-GCM、KDFはArgon2idのみ。
